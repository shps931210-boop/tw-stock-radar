# 股栗子

以學術研究、財務數據、技術分析與市場交易資訊為基礎的台股量化選股系統。使用者依投資策略自動篩選上市櫃股票，每個結果都能看到「符合了哪些條件、數字是多少」。

> **驗證狀態**（三件事分開看）：
> 1. **回測程式**：技術訊號有歷史回測（`app/backtest.py`），AI 名單每天事後追蹤（`app/track.py`）。
> 2. **回測結果**：目前沒有任何規則被證明能勝過大盤；門檻與權重是事先設定的，沒有用回測結果調整。
> 3. **樣本外績效**：只計算開盤前就公開存檔的名單，紀錄天數還少，不足以下結論。
>
> 「AI 量化評分」是固定規則的多因子計算，不是大型語言模型預測；只有「AI 研究助理」（含個股頁的「問問這檔股票」）使用大型語言模型（Claude，或沒有 Claude 金鑰時用 Cloudflare Workers AI 的免費開源模型），它會用資料工具查網站的個股、產業、新聞與績效資料再回答。分數是全市場相對排名，不是上漲機率，也不構成投資建議。

## 快速開始

```bash
cd tw-stock-screener
pip install -r requirements.txt

# 先用示範資料看網站（約 10 秒）
python -m app.update --demo
python -m app.server              # 打開 http://127.0.0.1:8000

# 換成真實資料
# 1. 到 https://finmindtrade.com/ 免費註冊，把 token 填進 config.json 的 finmind_token
# 2. 第一次完整抓取（回補約一年半股價，約 40~60 分鐘；財報依 FinMind 額度分批補齊）
python -m app.update
# 3. 啟動網站。之後平日 14:45、21:45 會自動更新，網頁上也有「立即更新」按鈕
python -m app.server
```

網站只顯示真實資料。還沒成功抓到行情時，會顯示「資料取得失敗」與錯誤紀錄，**不會自動改用示範資料**；要看示範畫面請明確打開 `http://127.0.0.1:8000/?demo=1`。`demo.html` 是不需要後端的示範版（`python build_demo.py` 重新產生），頂端有紅色「模擬資料」橫幅。

## 更新分三階段

第一次執行也不用等全部抓完才看到真實股價：

1. **最新收盤價**：用證交所 OpenAPI 一次抓最近一個交易日（幾秒鐘），完成後網站立刻顯示真實收盤價。
2. **回補歷史股價與籌碼**：約 40~60 分鐘。期間頂端會顯示「歷史股價回補中：目前 N 個交易日，需要 120 天」，技術指標與選股排行回補完成後才出現。
3. **月營收、財報、股利**：依 FinMind 額度分批補齊。

每個階段結束都會重算一次快照。所有請求遇到連線失敗、逾時、429、5xx 會自動重試兩次；錯誤訊息會寫出 HTTP 狀態碼或失敗類型（DNS 無法解析、被網路代理拒絕、回應格式改版）。

## 資料正確性原則

- 每個每日資料來源（上市／上櫃的行情、法人、融資、本益比）都記錄「最後成功的資料日」，網頁頂端顯示資料日期，哪個來源沒更新到會列出來。
- 判斷是否過期以**證交所實際公布到哪一天**為準（OpenAPI 回傳的資料日），國定假日、颱風假自動正確；連不到證交所時才用平日推估，並標明「推估」。
- 頂端分開顯示上市、上櫃股價的最後成功日期，「從未成功」與「過期」分開標示。
- 抓取失敗時保留上次成功的資料並標示日期，錯誤寫在「上次更新有 N 個警告」裡。
- 一筆真實行情都沒有時，不產生任何選股結果。
- 證交所主要端點（www.twse.com.tw 每日批次）抓不到最新一天時，會自動改用官方 OpenAPI（`openapi.twse.com.tw` 的 `STOCK_DAY_ALL`、`BWIBBU_ALL`，只有最近一日）補上；櫃買中心則用 `tpex_mainboard_daily_close_quotes`。
- 所有日期以台灣時間計算：程式一律用 `config.now()`（明確指定 Asia/Taipei），不依賴主機系統時區。
- **資料完整性**：品質、成長、估值、動能、趨勢五個因子都要有資料，才列入綜合排名、AI 排行與買點判斷；缺任何一項會標示「資料不足，暫不列入完整綜合排名」，不會把缺的資料當成 0 分。財報預設抓成交金額前 1000 檔（約涵蓋所有通過基本門檻的股票），設定 FinMind token 後約 3 天補齊。
- **各因子必要欄位**：財務品質至少要有 ROE、ROA 且五項中有三項；成長至少要有月營收年增與近三月年增且四項中有三項；估值要有本益比與股價淨值比；趨勢五項檢查至少四項。只有一兩項資料剛好很高的公司不會被當成高分。個股頁會顯示「資料完整度」與缺了哪些欄位。
- **過期資料不計分**：財報依法定期限（Q1 5/15、Q2 8/14、Q3 11/14、年報 3/31，加 10 天緩衝）判斷是否該有新一季；月營收 15 日後應有上個月；本益比最多比股價晚 3 個交易日。過期的欄位當作缺資料，個股頁標示「資料過期」。
- **籌碼與股價同一天**：法人、融資資料依交易日和股價合併，最多容許落後 1 個交易日，中間缺日或落後更多就顯示尚未更新，不拿不同日期的資料硬算。
- **除權息還原**：從證交所 TWT49U（上櫃另試櫃買端點）取得除權息參考價，均線、報酬率、波動率、技術訊號都用還原後的股價計算；顯示的收盤價仍是實際成交價。前收盤和資料庫對不上的事件不採用。
- **F-Score** 九項都能算才給分數；**EPS 年增率**在去年同季虧損時不計算，改標示「虧轉盈」或「持續虧損」。
- **OpenAPI 備援**：股價與本益比分開同步；當天只存了部分股票時會補齊；檔數比前一個交易日少一成以上視為不完整，不標記成功。
- **停止發布排名**：股價明確落後官方公布日時，網站仍會發布並顯示警告，但不產生新的 AI 排名與技術訊號。
- 目前只用**盤後資料**，不提供盤中即時報價（即時行情需向證交所申請授權並付費）。

## 部署：GitHub Actions ＋ GitHub Pages（免費、不需要自己的電腦開著）

`.github/workflows/update.yml` 每個交易日台灣時間 14:50、21:00 自動執行：抓官方資料 → 重算選股 → `python build_site.py` 產生靜態網站 → 發布到 GitHub Pages。資料庫存在 Actions 快取，每次只補新資料。

1. 把這個資料夾推到一個 GitHub repository。
2. Settings → Pages → Source 選「GitHub Actions」。
3. （建議）Settings → Secrets and variables → Actions 新增 `FINMIND_TOKEN`。
4. Actions 頁面手動執行一次「盤後更新」（第一次回補約 40~60 分鐘）。

可靠性設計：
- GitHub 的排程可能延遲或被略過，所以排了 14:40、16:30、21:00 三個時段；程式只補缺少的資料，重複執行沒有副作用。也可以在 Actions 頁面手動執行。
- 一筆真實資料都沒有時不發布，網站維持上一次成功的版本。
- 資料過期或某個來源失敗時（`python -m app.check`），這次執行會標成失敗，GitHub 會寄通知信；網站仍發布並在頂端顯示警告。
- 資料庫存在 Actions 快取；每次更新成功後另外壓縮備份到 repository 的 Release「db-backup」（只有公開市場資料）。快取被清掉時自動從備份還原，不必重新回補。每次備份後會下載回來做還原測試（解壓縮、完整性檢查、比對筆數與最新日期），結果寫在 `data/backup_status.json` 並顯示在可信度頁；備份或還原測試失敗時，這次執行會標成失敗並寄信，網站照常更新。

注意：GitHub 主機在國外，證交所是否會限制國外連線尚未實測；若被擋，錯誤會顯示在網站上，可改用台灣的主機或自己的電腦跑 `python -m app.server`。
不建議用 Vercel 這類 serverless 平台：單次執行有時間上限，無法完成第一次回補，也沒有地方存資料庫。

## 網站功能：一個網站、兩套選股系統

兩套系統共用同一個資料庫、指標計算（`app/metrics.py`）與選股引擎，所以兩邊的數字一定一致。

| 頁面 | 內容 |
|---|---|
| 首頁 | 大搜尋框、四個入口（今日買點／AI 量化選股／策略選股／自訂條件）、今日到達買點卡片、市場概況、「怎麼判斷到達買點」說明 |
| 技術訊號 | ① 通過 AI 均衡型硬性條件且分數 ≥ 55 ② 出現任一技術訊號（均線黃金交叉、KD 低檔交叉、MACD 翻正、帶量突破、回測月線）③ 沒有過熱（RSI、乖離、融資暴增）。**已有歷史回測，但結果並未證明能勝過大盤**，沒有出場規則，只是技術型態提醒，不是買進建議。規則在 `config.json` 的 `buy_point` 與 `app/ai_model.py` |
| 策略選股 | 12 套研究型策略各有一頁：概念、研究依據、風險、條件、符合股票，可一鍵套用到多因子篩選器修改 |
| AI 量化選股 | 穩健／均衡／積極三種模式，按「開始 AI 量化選股」產生關注排行榜，每檔附 AI 評估、主要原因、風險提示；可「查看 AI 使用的選股條件」並「用 AI 策略建立我的篩選器」 |
| 多因子篩選器 | 條件建構器（70 多個指標、八大分類）、AND／OR、儲存／編輯／複製／刪除策略、比較兩個策略、12 套研究型範本、「請 AI 分析我的篩選結果」 |
| 自選股 | 按 ☆ 收藏，記錄加入時價格並追蹤後續變化 |
| 指標資料庫 | 每個指標的公式、來源、頻率、方向、初始參數、研究依據、限制、回測狀態 |
| 個股頁 | 一句話結論、六面向雷達圖（品質／成長／估值／動能／趨勢／籌碼）、AI 解讀與進場時機檢查、AI 模型條件逐條對照、K 線／折線與均線、月營收、季 EPS、財報、法人、本益比、股利、新聞 |

AI 模型定義在 `app/ai_model.py`：每個模式有「硬性條件」（不符合不入榜）、「因子權重」（連續的百分位加權排名）與「參考條件」（只顯示，不影響排名）。
「AI 解讀」與「分析篩選結果」目前是依數據規則自動產生的文字，不是語言模型生成；之後可以接上 Claude API 產生更自然的說明。
儲存的策略與自選股存在使用者的瀏覽器（localStorage），之後要多人使用時再改存到伺服器。

## 三層選股

1. **排除不合格股票**：非普通股、20 日均成交金額 < 1,000 萬、交易日 < 120、長期虧損、處置股（`config.json` 的 `base_filter`）。
2. **策略篩選**：`app/strategies.py`。核心策略：優質企業、營收爆發、強勢動能、低估價值、多頭趨勢、綜合選股；進階策略：突破起漲、法人資金、穩健配息、低波防禦、F-Score、神奇公式。
3. **多因子評分**：品質 30%、成長 25%、估值 20%、動能 15%、趨勢 10%。每個子指標換算成全市場百分位後平均（`app/snapshot.py`）。

### 頁面重新整理（只載入已發布的資料）

每頁上方的資料列有「重新整理」按鈕。它只做「重新讀取已發布的資料」，不會向證交所抓資料，也不會觸發全市場重算：

1. 讀 `data/version.json`（`app/version.py` 產生，不經瀏覽器快取）。
2. `data_version` 和目前畫面相同 → 顯示「已是最新可取得的資料」與下次排程時間。
3. 不同 → 下載新版 `snapshot.json`（網址帶內容指紋，避開快取），檢查格式後才替換畫面；失敗就保留舊資料並說明。
4. 不整頁重新載入：保留捲動位置與還沒送出的輸入；AI 研究助理與帳號頁不重畫。
5. 頁面在前景時每 5 分鐘自動檢查一次，有新版只提示，不自動換掉正在看的資料。

`version.json` 的時間欄位分開：`trading_date`（行情交易日）、`fetched_at`（最後抓資料）、`calculated_at`（計算）、`published_at`（網站資料產生；GitHub Pages 上線還要幾分鐘）。`data_state` 目前只有盤後狀態：`postclose_final`、`postclose_partial`（有來源還沒更新或歷史不足）、`stale`（證交所已公布更新的交易日）、`unavailable`。內容指紋會忽略每次執行都會變的時間欄位，所以重跑同一份資料時版本不變。

盤中即時行情、會員申請局部來源更新、管理員全市場重算尚未實作：盤中資料需要確認來源授權，局部更新需要共享快取、限流與任務狀態表。

## 選股紀錄與數據品質與來源

- **每日選股紀錄**：每個資料日第一次完整更新後，把各模式前 20 名與技術訊號股票（含當時收盤價、分數、各因子分數、模型版本）寫進 `history/picks/日期.json`（首次發布版）；同一天稍後名單、排名、分數、因子分數、模型版本或資料日期有任何改變，另存 `日期.v2.json`（補正版，寫明原因）。檔案都不覆寫，GitHub Actions 會 commit 進 repository。
- **會員登入與雲端同步**（選用，Supabase）：在 Supabase SQL Editor 執行 `supabase/schema.sql`（Row Level Security，每人只能讀寫自己那一列），再到 GitHub repository variables 加 `SUPABASE_URL`、`SUPABASE_KEY`（只能放 publishable key；`build_site.py` 偵測到私密金鑰會拒絕啟用）。用 Email 登入連結／驗證碼，同步自選股、自訂策略、個人化選股偏好。每個帳號在瀏覽器裡有自己的一份資料（登出回到未登入的資料，不同帳號不會混在一起）；未登入時建立的資料要使用者按確定才會匯入。雲端資料有版本號，另一台裝置先改過時不覆寫，改載入最新版並提示。AI 問答只開放給登入會員：Worker 用會員的登入憑證呼叫 `use_ai_quota()`，每人每天 20 題、全站每天 100 題，任何檢查失敗都拒絕。沒設定時網站完全不顯示登入。
- **個人化選股**（`#/mine`，只在瀏覽器）：選關注期間（短／中／長）、風格（品質、成長、價值、高股息、動能）、風險偏好，從通過固定門檻（資料完整、有獲利、財務品質 ≥ 30、成交金額 > 3,000 萬、非處置股、依風險排除高波動）的股票中，依偏好重新加權排序；可隱藏股票、重設偏好、開關「從自選股學習」（同產業最多 +3 分）。客觀分數與風險提示不變；偏好存在 localStorage，還沒有帳號同步，也沒有回測。
- **產業熱力圖**（`#/sectors`，`app/sectors.py`，公開 `data/industry/latest.json`）：同一資料日、還原除權息；等權與市值加權（產業 8 成以上有市值才算）報酬、相對加權指數、上漲下跌家數、報酬分布、成交金額比（不是資金淨流入）、外資投信 5 日買賣超估算金額與覆蓋率、產業內 AI 高分股。停牌缺價計入覆蓋率；沒分類歸「未分類」。
- **財報與事件日曆**（`#/calendar`，`app/events.py`，公開 `data/events/calendar.json`）：證交所（上市）與櫃買中心（上櫃）除權除息預告為「已確認」，日期過了為「已完成」，預告表消失的未來事件為「未再確認」；月營收（每月 10 日前）與財報（Q1 5/15、Q2 8/14、Q3 11/14、年報 3/31）只標「法定期限（推估）」，不當成公司公告。清單／月曆、類型、只看自選股篩選；全部台灣時間。法說會尚未接上（沒有穩定官方來源前不顯示）。
- **智慧警報**（`#/alerts`，上方「通知」按鈕）：依自選股在網站內提醒（不寄信、不推播）：出現技術訊號、進入 AI 前 20 名、分數變動達門檻、新風險／不再通過門檻、已確認除權息前 N 天。通知代號固定（規則:股票:資料日），同一件事只通知一次；第一次只記錄基準。未登入存在這台裝置；登入後存在 Supabase `alert_rules`、`user_notifications`（唯一限制去重、只能改已讀、每人保留 500 則）、`alert_processing_state`，都有 RLS。`user_plan` 預留免費／付費方案，目前全部 free、不收費。判斷邏輯是 `static/index.html` 的 `<alert-core>` 純函式，`tests/test_alerts.py` 用 Node 測試。
- **投資儀表板**（`#/me`）：自選股今天的漲跌、AI 分數、技術訊號與風險；最新通知；14 天內的除權息與營收／財報期限；個人化選股前 5 名；加權指數與強弱產業。全部用網站已有的公開資料，在瀏覽器裡組合。
- **選股績效驗證**（`app/track.py`）：固定規則——選股日隔天開盤買進（算第 1 天）、第 5／20／60 個交易日收盤賣出（回測用同一個定義）、扣交易成本、還原除權息、等權重；基準是 0050（還原除權息）同一段期間（隔天開盤 → 出場日收盤）的報酬，基準固定是 0050，缺 0050 價格的紀錄標示「無法比較」，不改用其他指數，也不併入超額報酬平均；列出平均超額報酬、和「當天所有可排名股票」的差距、贏過基準的次數比例、最大回撤、再多 0.2%／0.5% 滑價的結果，並依模型版本分開統計。進場日停牌、漲停鎖死、成交金額不到 300 萬元的股票買不到，不計入並分類列出；出場日停牌或下市的股票仍計入，用最後成交價估算，並分成「之後已恢復交易」與「之後都沒有成交」兩類，另列只算有實際出場價的結果。也檢查 0050 在觀察期間有沒有缺資料。另有產業別表現、第 1 個交易日的結果、0050 總報酬與價格報酬並列，以及簡化產業歸因（名單比全市場多的部分 = 產業配置 + 同產業選股，等權，兩項相加等於總差異）。績效驗證獨立成 `#/performance` 頁，公開 `data/performance/summary.json`、`cohorts.json`。正式樣本外：只用首次發布版名單，而且名單要在進場日開盤（09:00）前就已存檔才計入；每筆紀錄存模型設定指紋（`model_hash`），同一版本號內設定有改過會在模型比較表警告。報酬同時列出「含估價」和「只算有實際出場價」兩種及估價比例。
- **入選後股價追蹤**：每天的名單從隔天開盤到同一個觀察日的變化；觀察日沒成交（停牌等）的股票不計入並列出檔數。持有天數不同，不能當成投資績效。
- **每日排名變化**：和上一個選股日比，均衡型前 20 名的新進榜、掉出榜（原因）、排名變動，以及分數變化最大的因子。
- **技術訊號歷史統計**（`app/backtest.py`）：訊號出現後隔天開盤買進、持有 5、20 個交易日；同一檔同一訊號有冷卻期不重複計入；扣交易成本 0.585%，和「所有股票、所有日子」對照。完整的「體質 × 技術訊號」規則還不能回測，因為沒有保存每一天當時已公布的財報。
- **產業比較**：金融業的財務品質與估值只和金融業比；個股頁顯示產業內排名（同產業至少 5 檔有分數）。
- **數據品質與來源**（網站 `#/trust`）：各資料來源最後成功日期、資料完整度與不足原因、模型版本紀錄、上面兩項統計。
- 模型版本定義在 `app/ai_model.py` 的 `MODEL_VERSION` 與 `CHANGELOG`，規則有改就要升版，紀錄裡會寫是哪一版選的。

## 測試與安全

- `python -m unittest discover tests`：不連網的核心測試（籌碼日期對齊、除權息還原、F-Score 完整性、財報過期、備援同步、資料不足不排名、管理員驗證）。GitHub Actions 每次更新前先跑，失敗就不更新網站。
- `/api/update`（本機版網站的「立即更新」）只接受本機連線；要公開部署時請設定環境變數 `ADMIN_TOKEN`，請求要帶 `X-Admin-Token`，手動更新至少間隔 10 分鐘。GitHub Pages 版是靜態網站，沒有這個端點。

## 已知限制與下一步

- **回測（第四階段）**：技術訊號已有簡易歷史統計；完整規則的回測尚未建立，要做到只用當時已公布資料、含交易成本與下市股票。
- 上櫃除權息端點尚未在真實環境核對；抓不到時上櫃股票的技術指標暫用未還原股價（網站資料 `adjusted_markets` 會列出已還原的市場）。
- 完整選股規則的歷史回測需要「當時已公布」的財報版本（point-in-time），目前只能靠每日紀錄往前累積。
- 上櫃資料解析需在本機實際跑一次確認；全額交割股尚未接資料。
- 金融業的負債比、毛利率條件標為「不適用」，但 ROA 等門檻仍不適合直接比較。
- FinMind 免費額度每小時約 600 次，財報預設抓成交金額前 1000 檔＋自選股（`fundamental_top_n`、`watchlist`）。

## 歷史資料長度

`price_backfill_days` 設為 1100 天（約三年）。最近 `recent_backfill_days`（420 天）以內一次補齊；更舊的日期每次執行只補 `history_dates_per_run`（60 個日期／市場），分幾天慢慢補完，避免單次執行超過 GitHub Actions 的時間限制。技術訊號統計會依年份、大盤多空（加權指數在 120 日均線上下）、訊號規則上線後（樣本外）分開列出。

## 問問這檔股票

預設是免費版：股票頁的「問問這檔股票」在瀏覽器裡依問題關鍵字（長期短期、財報、營收、風險、估值、股利、法人、技術面、AI 分數），用固定規則整理網站資料回答（`static/index.html` 的 `qaAnswer`），不花錢、不需要帳號。

### 選用：AI 研究助理（可以免費）

設定後，獨立的「AI 研究助理」頁（`#/ask`）和個股頁的問答改由 `worker/`（Cloudflare Worker）回答。AI 依問題呼叫資料工具（`worker/tools.js`），只讀網站的公開 JSON，不把整份資料送給模型：

| 工具 | 讀的資料 | 用途 |
|---|---|---|
| find_stocks | `data/ai/universe.json` | 名稱 → 代號 |
| get_stock_detail | `data/stock/代號.json` | 單一公司：指標、營收、財報、股利、法人、公告新聞 |
| compare_stocks | `data/ai/universe.json` | 2～6 檔並列比較 |
| screen_stocks | `data/ai/universe.json` | 依條件篩選全市場（最多 8 個條件、回傳 20 檔） |
| market_overview | `data/ai/universe.json`、`data/events/calendar.json` | 大盤、漲跌家數、產業報酬、前 20 名變化、未來兩週事件 |
| industry_report | `data/ai/universe.json`、`data/news/latest.json` | 產業概況、主要公司、最近公告與新聞 |
| search_news | `data/news/latest.json` | 公告與新聞（相似報導只留一篇） |
| performance_summary | `data/performance/summary.json` | 網站選股的事後績效 |
| explain_metric | `data/ai/universe.json` | 指標定義與限制 |

- `data/ai/universe.json` 由 `app/ai_data.py` 產生：全市場普通股的精簡指標，用「欄位 → 一整列」格式，Worker 解析快、CPU 時間短。
- 一題最多查 6 輪資料；回傳一行一個 JSON（查資料進度、回答文字、用到的資料來源）。回答要分開「資料顯示／可能的解讀／資料不足」，並註明資料日期。
- 對話紀錄只存在使用者的瀏覽器（依帳號分開，最多 30 段，可刪除）。

- 兩種模型，部署時自動選：
  - **免費**：只設定 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。使用 Cloudflare Workers AI（`worker/freeai.js`，模型在 `wrangler.toml` 的 `FREE_MODEL`，預設 Qwen3 30B），每天 10,000 Neurons 免費額度，用完當天停用。分析能力比 Claude 簡單。
  - **Claude（付費）**：再加上 `ANTHROPIC_API_KEY`（Anthropic Console 建立並儲值）。模型在 `MODEL`（預設 `claude-opus-5-5`；改 `claude-haiku-5-5` 約便宜 40 倍）。總花費上限請在 Anthropic Console 設定。
- 金鑰只存在 Cloudflare 的 secret，網站與 repository 都看不到；只接受股栗子網站來的請求，每個 IP 每分鐘最多 5 題，並且只開放登入會員（每人、全站每天有題數上限）。
- 部署：在 GitHub Secrets 加好金鑰，到 Actions 執行「部署 AI 研究助理」。部署後網址與模型種類寫進 `chat.json`，網站重建後聊天框才會出現；沒設定時網站不顯示聊天框。
- 測試：`cd worker && npm ci && npm test`。部署後工作流程會再用 `worker/smoke.mjs` 對剛部署好的 Worker 真的問三題（自由提問、追問、新聞），檢查有查資料、有來源、追問記得前文，結果寫在該次執行的摘要；失敗時網站不會換成新的 AI 網址。
